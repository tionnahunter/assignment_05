The main idea in this assignment was lineage: 
each pipeline step returns a wider copy of the frame and 
never changes the raw columns. In Step 1 I used vectorized .str
methods instead of apply. clean_employee_id needed .str.zfill(3) 
because "E4" has to become "E004" or the roster merge on employee_id 
won’t match it.

What I didn’t understand at first was errors="coerce" and NaT. 
I now understand that coerce turns unreadable values into NaN 
(or NaT for dates) instead of raising an error, and NaT is the date 
version of NaN. In parse_pay_date, I parse the column twice, once as
US dates and once as ISO dates, and use us.fillna(iso) to combine the 
results. Each pass leaves NaT where the other format applies. I still 
want practice predicting which values become NaT before I run the code.

tests. I assigned columns.name = None, which broke the lineage rule, and 
rename_axis(columns=None) fixed it. I used the wrong import path in the 
app, and I used the cleaned employee_id where the warning needed the raw 
employeeid. Reading the test output closely told me what to fix each time.
